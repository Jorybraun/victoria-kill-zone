# Actual native skeleton review evidence

These PNGs are generated by **the production `SkeletonAnatomyModel`, `SkeletonAnatomyLayout`, mesh decoder, and `HitSkeletonReveal`**, compiled directly from the application sources. They are synthetic SceneKit/Metal renders, not image generation, retouched illustrations, or physical camera captures. The rejected procedural model remains in slice 005 as history.

Regenerate from the repository root on a Mac with Xcode and Metal access:

```sh
bash scripts/skeleton-preview/run.sh
```

The script uses a disposable compilation directory and writes the durable evidence here. It loads the bundled `HumanSkeleton.vkskeleton` explicitly and fails if the actual production decoder/model rejects it; it does not substitute the old procedural model. If generated `scripts/skeleton-assets/work/skull-{source,packaged}.obj` comparison files exist, it also imports them through ModelIO, applies the production skull material, and renders them with the same camera and lights. These optional source references are separate from the runtime decoder and are not app resources.

`manifest.json` records the exact asset/source SHA-256 hashes, fixture inputs and measured fixture segment lengths, camera settings, scene times, visible geometry and positive-transform determinants, triangle counts, and individual PNG hashes. Source hashes matter because these renders may precede a commit. A later code or asset change requires regenerating the evidence before making a claim about that revision.

## Views

| Files | What they establish |
|---|---|
| `source-*` | Raw imported source-world geometry, before live pose retargeting, with production material/light settings. |
| `reference-skull-*` | Optional original-versus-converted head comparison; same camera and material, different geometry, source hashes recorded. |
| `neutral-*` | Front, rear, both profiles, and 45° views of the independent 1.75 m review fixture. |
| `silhouette-*` | Actual mesh geometry with a black constant material against a light background; no image editing. |
| `bent-elbows-*`, `crouch-*`, `turned-90-*`, `lateral-arm-*` | Placement from explicit synthetic observed-landmark inputs. Crouch preserves the defined femur and shin lengths. |
| `missing-left-wrist-right-ankle-*` | Removing input landmarks hides the dependent parts; absent points are not replaced with zero or invented. |
| `detail-*` | Skull, pelvis, shoulder/back, hand, and foot closeups. |
| `distance-*` | 60° vertical field of view, 1080 px height, 3/8/15 m camera distance on dark/gray/bright backgrounds. |
| `reveal-*`, `repeated-hit-*`, `stale-observation-*` | The actual shared production reveal controller/action sampled with deterministic SceneKit time and explicit observation timestamps. |

The review-world convention is subject left `+X`, superior `+Y`, anterior `+Z`, metres. Cameras are named by the side of the subject seen. The ordinary art views are orthographic; distance views are perspective. The neutral fixture is independent from the asset source pose and is not a measured ARKit bind capture. Hands, toes, and head roll remain cosmetic where input positions cannot establish their articulation.

Fixed review settings: production lights only, no default SceneKit lights, no HDR/auto-exposure/bloom, 4× MSAA, 1080×1440 standard images, square detail images. The material is the shipped ivory/rim shader; render output is not recolored afterward.

## Current disposition

**Integrate this replacement and continue the game.** Its anatomical structure is substantially clearer than the rejected slice 005 mesh. Final art acceptance remains open: skull seams/facial edges still show spikes and faceting; the wide neutral humeral fixture broadens chest/pelvis; the source foot template retains noticeable outward yaw. Those observations are tracked in [slice 006](../../slices/006-skeleton-art-direction.md) and are not a reason to hold the playable app under the user's current priority.

The original/packaged skull comparison localizes the additional vault spikes and torn nasal/maxillary edges to the conversion/simplification: the original has natural bone seams but fewer of these visible sliver artifacts. Keep that comparison as a concrete follow-up for the asset pipeline.

The rendered production reveal action reaches full opacity at 0/20/100 ms, fades to approximately 0.556 at 180 ms, and is hidden with zero opacity at 280 ms. Repeated hits reuse the same model and restart the existing action; stale input clears it. This demonstrates deterministic native scene behavior, not wall-clock latency on an iPhone.

No images here establish camera-to-body registration, independently sensed finger/toe pose, physical device frame time, thermals, four-player performance, or signing/release readiness. Those remain separate integration/device gates. The provisional 52,000-triangle cap is an integration budget, not measured performance evidence.
