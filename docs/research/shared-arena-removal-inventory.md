# Shared-frame / Saved Arena removal inventory (BIO-37)

Status: Research complete — 2026-09-27, read-only, against `main` at `3d89b7f82b218ef81b33858d1e3102c82a055785`. Feeds the product decision that Quick Duel (ADR 0013 body sighting, one AR frame per phone, `CombatRoom` as combat authority) becomes the **only** play mode and that the shared-frame / Saved Arena architecture (ADR 0010 / 0011 and the `SharedArena` / `DuelFrame` / MapLab / rendezvous code) is removed rather than extended. Builds on — does not repeat — [zero-step-architecture-synthesis.md](zero-step-architecture-synthesis.md) and its seven BIO-36 briefs; where those documents already establish a fact this brief cites them instead of re-deriving it.
Method: repository read of every path the removal touches (iOS app package, `CombatTransport` Swift package, `services/combat-worker`, `packages/combat-protocol`, `packages/combat-simulation`, `convex`, `spectator`, `scripts`, `contracts/fixtures`, CI workflows, `docs/decisions`), with dependents established by symbol search rather than by file name. Every claim about the repository is tagged **[repo]** with a path; every recommendation is tagged **[proposal]**; anything not verifiable from the checkout is tagged **[inference]** or stated as an absence. No physical-device behaviour is claimed anywhere in this document.

## 1. The question

What, exactly, must be deleted or simplified — file by file, across every workspace — to leave Quick Duel as the sole mode with no setup gate, while keeping `pnpm verify` green after every PR and preserving the paths `AGENTS.md` and the release process require (debug fire, the problem-report path, the release manifest)? Which ADR records the decision and which existing ADRs does it supersede?

## 2. Constraints this inventory must satisfy

From [AGENTS.md](../../AGENTS.md) **[repo]**: Phase 1 cap is four players; the archived repositories are reference-only and are not deleted or modernized; debug fire remains until physical markerless targeting evidence exists; `pnpm verify` is the canonical verification command; compile or simulator runs are not physical-device evidence. Ownership table: Integration owns repository-root configuration, shared contracts and models, the Xcode project, integration docs and release wiring; Backend owns `convex/**`; Spectator owns `spectator/**`; iOS targeting owns `ios/**/Targeting/**`; Design owns `design/**`. The table names no owner for `services/combat-worker/**`, `packages/**`, `ios/**/Features/**`, `ios/**/Services/**` or `ios/**/Domain/**`; this brief treats those as **ownership decisions**, not as facts (§7).

From the product owner (task statement, BIO-37): shared frame is removed and not coming back; start is never gated by a setup step; the target is 2–4 players with zero setup; the Convex lobby already knows the roster.

## 3. What the repository confirms today (evidence, not inference)

3.1 **Two independent verdict paths coexist.** `CombatSimulation` treats `rules.geometry === "sighting"` as a mode switch: readiness is `players.every(connected)` (no `frameReady`), `pose.observations` are ignored, `slowField` is refused with `invalidInput`, and `fire` resolves instantly through `resolveSighting` in the shooter's own camera space. Every other geometry (`trackedBody`, `phoneProxy`) takes the shared-frame path: `frameReady` gating, body-history from other observers, projectile flight through `colliderPairs`/`phoneAt`, and slow fields centred on a shared-frame pose. **[repo]** `packages/combat-simulation/src/index.ts` lines 133–138, 160, 205–216, 251, 279–300; `flight.ts` 139–160; `history.ts` 68–81.

3.2 **The two-player cap is enforced in three places, not one.** Client: `RealtimeAssociationPolicy.associateSighting` requires exactly one remote roster member and `QuickDuel.maxPlayers = 2` **[repo]** `ios/.../Features/Realtime/RealtimeBodyAssociation.swift`, `ios/.../Domain/LobbyModels.swift`. Server: `fire` under sighting returns `ambiguousTarget` when `opponents.length !== 1` and `invalidInput` when `observation.targetPlayerId` is not that single opponent **[repo]** `packages/combat-simulation/src/index.ts` 281–286. Lobby: `QUICK_DUEL_MAX_PLAYERS = 2`, enforced at `matches.create` (forces `maxPlayers`), `matches.join` (`QUICK_DUEL_FULL`) and `combat.prepare` **[repo]** `convex/functions/combat.ts` 27, 57; `convex/functions/matches.ts` 99, 149. Going to 2–4 therefore is a coordinated contract change, not a client-side constant edit.

3.3 **The shared-frame surface is not isolated.** Symbol search shows `SharedArena`/`DuelFrame` types consumed from `Targeting/TargetingSession.swift` (`DuelFrameSessionDriving` conformance), `Features/Realtime/*`, `Features/Game/DuelSession.swift` (peer shot tracer), `Features/Realtime/ReportProblemView.swift` and `Services/Realtime/MatchReportClient.swift` (`DuelFrameDiagnosticEvent`), `App/RootView.swift`, `App/AppEnvironment.swift`, `Features/Home/HomeView.swift`, and 24 test files **[repo]** (`ios/VictoriaKillZone/VictoriaKillZoneTests/` listing in §4.1).

3.4 **The report path is coupled to a `DuelFrame` type.** `MatchReport.log` is `[DuelFrameDiagnosticEvent]` and `ReportProblemView.loadLog` returns the same type; the Worker renders `report.log` as "Setup log (untrusted)" with `{elapsedMs, kind, detail}` **[repo]** `ios/.../Services/Realtime/MatchReportClient.swift` 12; `ios/.../Features/Realtime/ReportProblemView.swift` 15; `services/combat-worker/src/report.ts` 22, 241, 265. Deleting `DuelFrameDiagnostics.swift` wholesale would break the protected report path; it must be renamed and kept (§4.1, §5).

3.5 **The Xcode project lists every source file explicitly.** `project.pbxproj` uses `PBXFileReference` entries (161 references; 207 lines mention shared-frame file names) rather than file-system-synchronized groups, and `scripts/ci/check-xcode-sources.py` (run by `scripts/ci/verify-ios.sh`) fails when the Sources build phase and the on-disk `*.swift` set differ **[repo]**. Every iOS file deletion therefore requires a paired `project.pbxproj` edit, which is Integration-owned.

3.6 **The `CombatTransport` Swift package is used only by shared-arena code.** `import CombatTransport` appears in exactly four app files (`ArenaLinkMessage.swift`, `CombatTransportArenaLink.swift`, `FallbackArenaPeerLink.swift`, `ArenaLinkFrameMapper.swift`) plus `EngineLinkageTests.swift`; `CombatTransportError` in `Services/Realtime/CombatSocketTransport.swift` is a separate, locally defined enum **[repo]**. After removal the package (`ios/VictoriaKillZone/Transport/CombatTransport`, declared in `ios/VictoriaKillZone/Package.swift` and built by `verify-ios.sh`) has no consumer.

3.7 **`frameEpoch` is threaded through every layer, but only the map route and ticket give it meaning.** Protocol: `CommandEnvelope`, `CombatSnapshot`, `ServerEvent`, `CombatTicketClaims`, `CombatProjection` all carry `frameEpoch` **[repo]** `packages/combat-protocol/src/index.ts` 88, 132, 139, 162, 168. Worker: room bootstrap stores `frame_epoch`, command envelopes are rejected with `epochMismatch` on disagreement, map route is `/v1/matches/:id/frames/:frameEpoch/map`, `authorizeMap` compares claim, snapshot and route epochs **[repo]** `services/combat-worker/src/room.ts` 59, 85–105, 304; `routes.ts`; `store.ts` 45, 58–63. Convex: `combatFrameEpoch` column, ticket claim, projection idempotency check **[repo]** `convex/functions/schema.ts` 67; `convex/functions/combat.ts` 92, 123. Nothing in the sighting path reads `frameEpoch` except as an equality check; the value is always `1` in fixtures and deploy smoke (`contracts/fixtures/combat.v1.json`; `scripts/release/combat-deploy.mjs` 229) **[repo]**.

3.8 **`calibrating` is the initial phase for every geometry.** `CombatSimulation.create` starts at `phase: "calibrating"`; host `start` moves to `running` once `coverage()` holds, which under sighting is simply "everyone connected" **[repo]** `packages/combat-simulation/src/index.ts` 26, 232–237. Convex writes `combatPhase: "calibrating"` at prepare and the schema enumerates it; spectator labels it "ALIGNING ARENA" / "ALIGNING" **[repo]** `convex/functions/combat.ts` 64; `spectator/src/components/MatchHeader.tsx` 24, 80–81. The phase name is shared-frame vocabulary, but the state ("prepared, waiting for host start") is still needed under Quick Duel.

3.9 **`rulesSchemaHash` freezes the *shape* of `CombatRules`.** `scripts/ci/check-release-manifest.mjs` bundles `combat-protocol`, computes `sha256(JSON.stringify(rulesSchemaKeyPaths(DEFAULT_RULES)))` and fails if it differs from `release-manifest.json` **[repo]** lines 110–120. Removing `geometry` or `slowField` from `CombatRules` changes the key set and therefore the manifest; changing only the *value* of `geometry` does not.

3.10 **Worker storage has no migration path for dropping tables.** `store.ts` creates `schema_migrations` at version 1 and creates `shared_maps` / `map_chunks` with `CREATE TABLE IF NOT EXISTS` **[repo]** lines 41–66. There is no `DROP TABLE` or version-2 step; the BIO-36 synthesis already recorded this absence.

3.11 **Debug fire is a Convex/classic-mode path, not a shared-frame path.** `VKZ_DEBUG_FIRE || DEBUG` gates the "CLASSIC DUEL · 2 PLAYERS" button in `HomeView.swift` (line 102) which calls `store.createDuel()` → `performCreateDuel()` with `combatMode == nil`; the classic path is `DuelSession.swift` + `ActiveDuelView` + Convex `shots.*` mutations with `convex/domain/fire.ts` and the `contracts/fixtures/g2.v1.json` fixture **[repo]**. The *peer shot tracer* inside `DuelSession` (`sendPeerTracer`, `updateDuelPeerLink`, `ArenaShotTracer`, `DuelPeerLink`) is a separate Bonjour/`CombatTransport` presentation channel that predates the Worker; it carries a ray in a frame no peer shares. It is shared-arena code, not debug-fire code (§4.1, item I-14).

3.12 **Absences.** No Convex table stores arena bundles, world maps or transforms; Saved Arenas are device-local (`Services/SavedArenaStore.swift`, `Services/MapLabStore.swift`) **[repo]**; the only server-side map storage is the Worker's `shared_maps`/`map_chunks`. No ADR 0012 file exists in `docs/decisions/` although ADR 0013 refers to it **[repo]**. No physical-device evidence for any shared-frame or sighting behaviour exists in the repository beyond the trial note ADR 0011 cites; this brief makes no device claims.

## 7. Open decisions (owner input needed)

- **D-1 — How does the client choose `targetPlayerId` with 2–4 opponents?** The repository has no mechanism: sighting association is "the only other connected player" on both client and server (§3.2). Candidates **[proposal]**: (a) host-assigned per-match visual identifiers (colour/tint) recognised by the shooter — needs new targeting work; (b) treat any sighted body as "an opponent" and let the shooter pick the nearest roster member by lobby-supplied approximate bearing — no such bearing exists today (absence); (c) accept an *unidentified* opponent hit and let the server attribute by exclusion (only works at 2). This decision is outside a removal inventory but gates step 6; it is the single largest unknown and should be its own research slug.
- **D-2 — Protocol bump or dead fields?** (a) v2 with `frameEpoch`/`frameReady`/`slowField` removed (clean, touches manifest, fixtures, Convex schema, spectator); (b) keep the fields pinned to `1`/`false`/unused under v1 indefinitely. Recommendation: (b) through step 6, then (a) as step 8 when the team is ready to run the rollback runbook.
- **D-3 — Delete or keep the `CombatTransport` Swift package** (I-20).
- **D-4 — Compatibility window for `combatGeometry` in `matches.create`** — accept-and-ignore for one release or reject immediately.
- **D-5 — Is the classic-mode peer tracer (`DuelPeerLink`, ADR 0005 visible shots) debug-fire scope?** This brief says no (§3.11); the owner of the debug-fire guarantee should confirm.
- **D-6 — Ownership of `services/combat-worker/**`, `packages/**`, `ios/**/Features/**`, `ios/**/Services/**`, `ios/**/Domain/**`** — unassigned in `AGENTS.md`; assigned here to Integration* provisionally. The BIO-36 synthesis raised the same gap.
- **D-7 — Phase rename** (`calibrating` → `ready`/`lobby`) — bundle with D-2(a) or leave the literal.

## 8. Risks

1. Report path regression if `DuelFrameDiagnostics.swift` is deleted rather than renamed (§3.4) — mitigated by step 3 ordering and an unchanged wire shape.
2. `verify-ios.sh` failure on any pbxproj drift (§3.5) — every iOS PR must pair deletions with project edits; only a macOS runner catches this.
3. `rulesSchemaHash` mismatch if a `CombatRules` key is removed outside the manifest PR (§3.9).
4. Convex schema push rejecting stored `trackedBody`/`phoneProxy` rows if literals are narrowed too early (C-3).

6. Worker store: first SQL migration in this codebase (W-4); test on a fresh and on a pre-populated DO.
7. The 2–4 identity problem (D-1) has no repository solution; removing shared frame does not by itself deliver 3–4 players — it only removes the alternative the copy currently points to.
