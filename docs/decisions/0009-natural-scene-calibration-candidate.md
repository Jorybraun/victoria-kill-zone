# ADR 0009 — Natural scene reference for the calibration candidate

Status: accepted implementation scope, 2026-09-05, under the owner's full-review authorization and direction to finish the native game before further server work. Physical acceptance and unrestricted arena movement remain open. Integration owns the native bundle contract and player-facing composition; targeting owns capture and measurement.

The existing map-seeded frame provider could never finish setup: it required three fresh independent residual measurements but had no measurement source. A saved map anchor only repeats stored coordinates. A player's phone is independently movable relative to their head, so the head-to-phone offset proposed in ADR 0006 cannot establish translation or orientation accuracy.

The implementation uses an existing stationary textured rectangle in the scene. No marker is attached to a player or added to the play area. The host centers a suitable surface, captures three distinct Vision rectangle observations with rays intersecting the same observed plane, and checks geometry and stability. The crop is perspective-corrected; its image, measured physical dimensions and rigid map-space transform accompany the secure world-map archive. Unsupported or unreliable surfaces remain a recoverable setup state.

The authenticated map endpoint continues to store opaque bytes with its existing 8 MiB limit and SHA256 identity. Native `DuelFrameCalibrationBundle` versions the internal payload. A legacy raw AR archive remains decodable but has no independent reference and cannot open readiness. This changes native payload interpretation, not the combat server protocol or authority selection.

Both world and body configurations install the same reference image. Only a matching, actively tracked image-anchor sensor update, tied to a fresh delivered camera frame, can yield a residual. Cached anchors, repeated timestamps, wrong epochs and invalid rigid transforms cannot refresh permission. Lost reference observations revoke readiness. Apple exposes [image detection on body tracking](https://developer.apple.com/documentation/arkit/arbodytrackingconfiguration/detectionimages) and [continuous image tracking](https://developer.apple.com/documentation/arkit/arbodytrackingconfiguration/maximumnumberoftrackedimages); the installed SDK declarations were also checked. These APIs do not promise this game's spatial accuracy.

The existing 100 ms pose and residual freshness, three consecutive good samples, 10 cm translation and 0.5° orientation limits stay unchanged. The reference comparison checks full rotation, which is stricter than checking yaw alone. This candidate requires the reference to remain visible during combat. It is suitable for measuring the shared-frame approach; it does not establish unrestricted free movement. The UI shows the actual reference thumbnail, capture failures and visibility requirement.

The limits are not a complete target-space error bound: 0.5° contributes roughly 13 cm lateral error at 15 m before translation and body uncertainty. Current observed-body admission also adds 5 cm to translation residual and caps uncertainty at 10 cm, so that path effectively requires translation residual at most 5 cm. Range-dependent accuracy, body coverage and the usable play-area arrangement must be measured together. Do not relax freshness or manufacture residual success to claim the full game is validated.

Verification includes bundle/hash/size/type checks, independent geometric residual fixtures, fresh sensor identity, lost visibility, map compatibility, async capture cancellation, the complete native suite and an unsigned iOS build. Acceptance additionally requires two/four physical phones: capture suitability, map/body relocalization, reference visibility with opponent body coverage, alignment at 3/8/15 m, walking/ducking, interrupted/background sessions, frame time and thermal behavior. No such physical result is recorded by this decision.
